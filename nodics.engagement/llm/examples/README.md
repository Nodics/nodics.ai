# Customer Engagement Examples

## Supported activation

A runtime activates `nodics.engagement`; the group resolves all seven children in index order. A project may leave `engagement.capabilities.customerReview` disabled while retaining the stable package graph.

## Supported customization

A customer project adds a later-loaded contact extension module and overrides only its routing policy. It preserves the `nodics.engagement` identity and does not copy the framework group or archived CRES implementation.

## Safe Communication absence

Before `nodics.communication` is restored, an accepted domain action must not claim delivery. `engagementComms` stays dormant or returns a recoverable deferred outcome without rolling back valid Engagement data.

## Rejected designs

- Adding domain schemas or routes under the group root.
- Removing a required child to disable a feature.
- Calling residual `DefaultNotify*` or Customer Review generated artifacts as current authority.
- Putting provider credentials, tenant ids, permissions, or retention durations directly in source.
