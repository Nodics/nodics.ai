# Enterprise Participation Capabilities

Explicit Init `digitalCore:enterpriseParticipationAccess@0.0.1` owns internal
capability groups only, not a new selectable profile or enterpriseRole. Existing
read/transaction definitions remain unchanged. It defines parent-free
`digitalEnterpriseSettingsUserGroup`, whose sole permission is
`commerce.digital.bundle.configure`. The separate pinned Init prerequisite
`enterpriseParticipationPermissions@0.0.1` creates that permission first.
Numbered headers order finalization, not finalized record-file dispatch. Putting
the new permission beside its dependent group can dispatch the group first and
correctly fail Profile vocabulary validation. Use the release dependency, never
weaken that guard. A route declaration is not persisted permission authority.

The effective union is own Digital read/reveal, bundle manage and bundle
configure. It contains no merchant, runtime, platform administrator, wildcard,
financial funding, publication approval or activation permission. Existing
merchant and customer groups are unchanged. Cart, Checkout, Bidding, Order and
Loyalty responsibilities remain with their owners and are separately composed
by reviewed existing profiles. Use existing Admin for administrative tests; no
task-specific manager roles or new aliases. Installation assigns nobody.

All records use Profile insert-missing `ensureReferenceAll`. Same-type Init
dependencies pin existing vocabulary/groups before this role. Preserved inactive
or narrowed definitions require explicit governed review, never import repair.
Applications select definitions before their separate Sample assignments; Sample
manifests cannot depend on Init releases. Use Profile's current persisted role
union and normal stamp owner for assignments, never role maps in configuration.

This role does not enable any gift/coupon policy or bypass ownership, current
Profile scope/DENY, Store, recipient, immutable holds, private persistence or
publication qualification. Settings remain audited owner commands with original
human credentials, signed Enterprise, revision and idempotency checks.
`test/digitalEnterpriseRoleBaseline.test.js` verifies the exact union through
actual participation admission, including missing permission, DENY and foreign
alias refusal. No live setting or grant is changed by those tests.
