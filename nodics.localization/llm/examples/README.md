# nodics.localization examples

- Operator: inspect English/Arabic coverage, open missing and review queues, edit through backend schemas, approve, build a release, publish through nPublish, and rollback by publication code.
- Protected rejection: a tenant editor cannot override a protected authentication message; only the configured protected administrator can do so when the key permits that scope.
- Provider recovery: translation memory is checked before an optional machine provider. Provider outage blocks only suggestions, not manual editing or published bundle reads.
- Customization: a project contributes new keys under its own owner module, adds supported locales or fallback policy through layered configuration, and selects provider adapters without changing Localization source.

A future checkout validation message is owned as a stable key by Checkout, stored and published by Localization, resolved through the Core client, and rendered by the browser using the returned `LocalizationContext`. A product name remains Product-owned localized data and is not copied into a generic message bundle.
