# Nodics Incident Response

When a production or security incident is suspected, respond with discipline.

## First actions

1. Identify the affected module, runtime server, tenant, enterprise, and data
   scope.
2. Preserve logs, traces, audit records, and release versions.
3. Assess tenant isolation and whether private media/data exposure is possible.
4. Check for generated-route bypass, service-token misuse, human-token misuse,
   or incorrect module activation.
5. Choose containment before broad remediation.

## Follow-up

Every incident follow-up must document root cause, affected contracts, customer
impact, tests added, release branches patched, and operator action.
