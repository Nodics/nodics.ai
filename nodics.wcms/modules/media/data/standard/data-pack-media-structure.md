# Standard Data-Pack Media Structure

Media referenced by content, product, documentation, accelerator, import, export, or customer data must travel with the data release as a single importable unit.

Required package layout:

1. `data/manifest.json` is generated by Nodics tooling and includes release
   asset checksums when media records reference physical files.
2. `data/<dataType>-vNNN/headers/` contains the media import header that routes
   records to `media.media`.
3. `data/<dataType>-vNNN/records/` contains media object records with business
   metadata and an import-only `asset.sourceFile`.
4. `data/<dataType>-vNNN/assets/` stores the physical files referenced by those
   media records.

The import process must fail or remain pending when required media artifacts are missing, checksum mismatched, blocked by policy, or not approved for target usage.

Media records must not declare provider-owned storage fields. Runtime storage
metadata such as provider code, storage key, relative path, URL, size, checksum,
and ready status is resolved by nImport and nMedia when the release is imported.

Example record:

```js
module.exports = {
  homeHeroImage: {
    code: 'homeHeroImage',
    name: 'Home hero image',
    folderCode: 'cmsAssets',
    formatCode: 'original',
    businessPurpose: 'contentMedia',
    ownerType: 'CMS_COMPONENT',
    ownerReference: 'homeHeroComponent',
    reusable: true,
    asset: {
      sourceFile: 'assets/cms/home-hero.webp',
      checksum: 'optional-sha256-value',
      checksumAlgorithm: 'sha256'
    }
  }
};
```

Publication copies media through the media publication transfer contract. Staged
storage keys are never authored as Online or disaster-recovery paths.
