# Nexus Web Data Contracts

This folder contains maintained AI/developer contracts for the Nexus Web Data boundary. Keep this README concise and put only durable module-specific rules here.

- Follow the root and ancestor AGENTS chain before changing this package.
- Keep detailed publishable documentation in the owning documentation/content-pack source.
- Regenerate module context after metadata, README, AGENTS, source, data, or test changes.

This pack is owned by the Nexus accelerator. Preserve `nexus.web` and existing
release codes/versions/checksums; customers extend it from their own content modules.
Use the owner-scoped `nexus:check` tooling command. Do not import content during
module startup or move browser source into this backend pack.

Derived component-media records exclude retired source components. Keep surviving
binding codes stable, retain owner validation and advance the development manifest
version/checksum when correcting a previously attempted release.

The unreleased Editorial source baseline imports article masters as DRAFT without workflow, approval or publication evidence. Ready sample localization copy does not approve an article. Operators validate and submit each draft through Editorial, review through Process, and inspect the actual nPublish request before claiming Online delivery. This source correction does not rewrite installed records or receipts.

Corporate localization uses `cmsComponentLocalization`, declared localized type properties and locale-scoped routes. Keep one shared page/component identity and published language links; never store translated business copy in frontend code or Kickoff defaults. A READY translation still requires normal publication approval.

The immutable manifest uses deterministic file order: component type declarations and components must precede localized variants. Verify this against the installed predecessor, not only an empty schema. Retain a failed source receipt and advance the release for a correction.
